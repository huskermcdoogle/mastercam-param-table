    Load the changes

    Mastercam: Lathe params - load

    What this is for

    The load reads your saved workbook and puts the changed values back into the ops. First it shows a window with every change, op by op: the old value crossed out in red, the new value in green. Each change has a tick box. Nothing is written until you click Apply.

    When to use it

    When you are happy with your edits in Excel and have saved the workbook.

    Steps

    1. Save the workbook in Excel (Ctrl+S). You can leave it open.
    2. In Mastercam, open the same part and click Lathe params - load.
    3. Pick the workbook. The file window starts on the one you dumped last for this part. Click Open.
    4. Read the top line: the whole part's cycle time and insert flips, before and after.
    5. Read the list. Each op shows its own time and flips, then each change. Untick anything you want to leave out. Unticking an op unticks all of its changes. The top line follows.
    6. Look at the Refused part, if there is one. Those rows are not written at all (see below).
    7. Under the list, the box Regenerate the ... changed operations after loading is not ticked. Leave it that way unless you want to wait for the regeneration now (see Regenerate below).
    8. Click Apply (it says how many, e.g. Apply 4 changes), or Cancel to write nothing.
    9. Regenerate the changed ops (they are marked dirty), check them, then save the part.

    Some changes tick together. A feed and its feed_mode (per rev / per min) go together; so do a speed and its CSS / RPM, and a value and the switch that turns it on. Half of a pair would make no sense.

    Worked example

    You changed the bore feeds (ops 7 and 8) and the facing speed (op 1). The preview shows:

    OperationParameterNowWill be
    op 1 · FACEspeed200250
    op 7 · ROUGHfeed0.010.012
    op 8 · FINISHfeed0.010.012

    You decide to wait on the facing speed. Untick op 1. The top line drops back to the bore changes only. The button now reads Apply 2 changes. Click it; regenerate ops 7 and 8.

    Regenerate – only when you choose

    After a load, the changed ops are marked dirty: their toolpath is still the old one until Mastercam regenerates them. On a big part that can take a long time – twenty minutes or more – and Mastercam cannot be used while it runs. So the tool never regenerates by itself. You pick the moment, one of two ways:

    1. Right away: in the load window, tick Regenerate the 2 changed operations after loading - can take a long time on big parts, then click Apply. The box starts unticked every time.
    2. Later: click Lathe params - regenerate last load (on the Parameter Table tab). It lists the ops the last load changed and which still need it, and warns about the time. No is the default – click Yes to start.
    3. When it is done, a message gives Mastercam's own cycle time for those ops beside the estimate the workbook showed. Save the part.

    Either way the result goes into the part's history: each op's estimate and Mastercam's time after. That is the check on the estimate. If every op is regenerated already (you did it by hand), the command only reads their times – nothing is regenerated again.

    Worked example

    You loaded new feeds into ops 7 and 8, then ran Lathe params - regenerate last load at lunch:

    OpBefore the loadEstimate afterMastercam after regeneratingDifference
    op 7 · rough bore0:41:100:34:200:34:31+0:00:11
    op 8 · finish bore0:12:050:10:050:10:02-0:00:03
    Both0:53:150:44:250:44:33+0:00:08 (+0.3%)

    The message says: Mastercam's cycle time for them: 0:44:33. The estimate was 0:44:25 - Mastercam's is 0:00:08 longer (+0.3%). The estimate was right to within seconds, so the 8:50 a part it promised is real.

    What the messages mean

    A refused row is left out whole – half a row is a state nobody chose. The reason is beside it:

    "0.5" is above the maximum ... / ... is below the minimum ... / ... is not a number
    A value is outside what Mastercam takes for that setting. Fix the cell, save, load again.
    "..." is not one of: ...
    A dropdown cell has something typed in that is not on its list (a typo in per rev, a coolant name).
    is 131 characters; the operation holds at most 119
    A comment or text is too long. Shorten it – the tool will not cut it off for you.
    "feed" is read-only here but was changed ...
    You typed in a column the load never writes (a time, a count, an ID). Put the old value back.
    "..." does not apply to a FACE operation ...
    That cell is greyed out for that kind of op. Clear it.
    no ROUGH operation with that number is in the part / ... is a different kind of operation
    The workbook was dumped from another part, or the op was deleted or replaced since. Dump again.
    Save the part first ...
    No saved part is open in Mastercam.
    ... could not be opened (is it still open in Excel?)
    Save the workbook in Excel and try again. If it still fails, close it in Excel.
    Wrote 2 operation(s). They are marked for regeneration ...
    Done. Regenerate before you post, or the old values are still in the toolpath.
    Regenerated 2 operation(s) in 0:12:31.
    The regeneration you asked for is done. The cycle times are in the part's history. Save the part.
    ... 1 had been regenerated already.
    That op was clean, so it was not regenerated again – only its cycle time was read.
    ... 1 FAILED - see ParamTable.log.
    Mastercam could not regenerate that op. Open it in Mastercam to see why (missing geometry, a stock problem), fix it, and regenerate it there.
    Mastercam is still regenerating in the background, so the cycle times were not read.
    Wait until Mastercam is done, then run Lathe params - regenerate last load again: it reads the times without regenerating again.
    Mastercam is regenerating operations already, so nothing was started.
    Mastercam was busy with its own regeneration. Wait until it is done and try again.
    No load of ... was found ...
    The part has no load in its history or in ParamTable.log, so there is nothing to regenerate.

    Every old value goes into ParamTable.log beside the part first. That is how undo last load puts them back.
