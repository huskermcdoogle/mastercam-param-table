    Program check

    Ribbon: Parameter Table tab › Improve › Program check

    What this is for

    A second pair of eyes. It looks over every op and makes a Program check sheet of findings. Each finding says why it matters, how to fix it, and links to the op. Look at findings are worth a look before the program runs; FYI ones are just good to know. It changes nothing.

    When to use it

    • Before a program goes to the floor for the first time.
    • After you edited a lot of ops.
    • When you take over a program someone else wrote.

    Steps

    1. Click Program check. The Program check sheet opens.
    2. Read the Look at findings first. Read why it matters and how to fix.
    3. Click the op link to go to that op's row. Fix it there (or in Mastercam).
    4. If a finding is fine as it is (you meant it), type x in its Ignore column. It stays ignored next time you check – even after a new dump.
    5. Run the check again after your fixes.

    What it looks for

    FindingWhy it matters
    An insert's edge runs much longer than usual (the main check)The edge may wear out, chip or break before the stop. “Usual” is the Usual edge time you type for the insert on the Tools page – or, if blank, the same insert on your other tools.
    The same tool at different speeds or feedsOften a copy-paste slip. Sometimes on purpose (rough vs finish).
    CSS with no max RPMNear the center, CSS asks for a huge RPM. Set a max RPM.
    Coolant off on a cutting opUsually forgotten. Dry on purpose? Ignore it.
    Lots of air cuttingTime spent cutting nothing. Tighten the stock or the start point.
    Extra tool changesThe same tool called again right after another – ops that could be next to each other.
    Ops needing regenerationThe toolpath is out of date. The times on the sheet are too.
    Ops with no commentThe setup sheet and the operator see a blank name.
    A feed that looks like the wrong unit0.012 per minute crawls; 12 per rev crashes. One of them is wrong.

    Two things it does not do: it never flags tool inspection being off by itself (plenty of ops need no stops), and the words in an inspection comment do not decide what it counts as a flip.

    Worked example

    You typed a usual edge time of 8:00 for the C 80° r0.031 insert. Tool T12 (the bore bar) runs it for 11:31 between flips.

    KindFindingHow to fixIgnore
    Look atT12: the edge cuts 11:31 between flips; usual for this insert is 8:00Shorter edge time (insp_time) on ops 7 and 8, or a lower speed
    FYIOp 13 has no commentType a commentx

    After you set insp_time to 8:00 on ops 7 and 8 (with Inspection & inserts) and check again, the first finding is gone. The second stays ignored.

    What the messages mean

    No findings.
    Nothing to look at. (Ignored findings are not shown.)
    A finding came back after a new dump
    It is a different finding now (a different op or value), or it was never ignored. Type x again.
